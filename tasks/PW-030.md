## 인수 조건 / 먼저 작성할 시험
- REQ-030-A / TST-030A: 실제 실행한 provider와 미실행 adapter를 구분한 보고서가 있다.
- REQ-030-B / TST-030B: 계정/약관/비용 미승인 상태를 테스트 통과 또는 v1 전체연동 완료로 기록하지 않는다.

TDD: 자동화 가능한 조건은 재현 fixture와 failing assertion부터 만든다. 정책·실환경·사람 판단은 manual evidence로 별도 기록하며 가짜 자동 pass로 대체하지 않는다.

## 구현 체크
현재 코드·계약 확인 → normal/failure/cancel/duplicate 경로 검토 → 필요한 DB/API 변경 및 compatibility 확인 → 최소 구현 → regression. 실제 비밀/미공개 원문 대신 synthetic fixture를 사용한다. 이미 통과한 user data protection 조건을 약화하지 않는다.

## 산출물
구현 또는 spike 보고서, TST-030A/TST-030B의 실제 검증 증거, 실행 명령/exit code, UI 변경 시 브라우저 증거, 미실행/blocked 이유, 남은 위험. 문서만 만든 경우 implementation_complete로 기록하지 않는다.
